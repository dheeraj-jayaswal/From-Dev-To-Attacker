The stack (so the bugs make sense)

Angular SPA (client-side routes/guards = advisory only) · Express/Node with two API surfaces: /api/* (auto-generated Sequelize CRUD → mass assignment/IDOR) and /rest/* (hand-written logic). Data in SQLite (SQLi) + a MarsDB NoSQL store for reviews/orders (NoSQL injection). JWT is RS256 with the public key bundled (forgery). Files: static /ftp (traversal/null-byte) and complaint/B2B upload (XXE, zip-slip, YAML bomb).

Method & grading

Work each category top-down by difficulty. For every solve, write a finding card (see Reporting). Discovery is white+black box — you have the source, use it; that's your dev edge.

Finding evidence (your exploit's confidence):
VERIFIED reproduced w/ impact · STRONG indicator · WEAK anomaly · THEORETICAL plausible
Factual claim (CWE/CVE/version):
FACT: Verified · FACT: Likely · FACT: Unverified
Difficulty: ★ → ★★★★★★ as on the Score Board.
The two scales stay separate (your house rule): a reproduced exploit does not make its CWE/CVSS verified. Every mapping below is graded on its own; anything needing a live secret is flagged, never fabricated.

TITLE:            e.g. Mass-Assignment Privilege Escalation in POST /api/Users
AFFECTED:         endpoint / component / parameter
EVIDENCE:         VERIFIED | STRONG | WEAK | THEORETICAL     (reproduction state)
ATTACK SCENARIO:  realistic, incl. chains across surfaces
BUSINESS IMPACT:  domain-specific
CVSS:             v4.0 vector + score (show reasoning; state the version the client requires)
CWE / OWASP:      id  [FACT: Verified | Likely | Unverified]   (graded SEPARATELY from EVIDENCE)
PROOF:            request/response, screenshots
REMEDIATION:      code/config-level fix
