Phase 0: Mindset Shift + Lab Week 0–2

Goal: Stop thinking "how should this work" and start thinking "how can this be abused". Build a safe lab and a note-taking habit.

Why it matters for a developer: You already read code and understand HTTP, auth, ORMs and frameworks. That is a real advantage in web testing. The gaps are networking, Windows/AD, Linux depth and attacker tradecraft.

🐧 Linux Core Skills — Pentester and Red Teamer Baseline Phase 1 · months 1–2

Why this section exists. Linux is your daily workstation and a common target, for pentesters and red teamers alike. Developers often know enough Linux to ship code but not enough to enumerate, escalate, pivot or audit a host. Do this alongside Phase 1 and use the gate below as the checkpoint. Practice only in your own lab or an authorized engagement.
🚦 Linux readiness gate (pass 7 of 9, in your own lab).
  1. Build a pipeline that parses a log or scan output and summarises it, without looking up the syntax.
  2. Explain a SUID, a capability and a sudoers rule, and find all three on a fresh VM.
  3. Set up key-based SSH through a jump host and use local, remote and dynamic forwarding. State what traffic each carries.
  4. Write a systemd service plus timer and read its logs in two places.
  5. Use ss, ip and tcpdump to explain a live connection, then block it with the firewall.
  6. Script a host/port check in Bash and Python with timeouts and JSON output.
  7. Root two deliberately vulnerable Linux lab machines manually, then write the root cause and fix for each.
  8. Authenticate to an AD lab from Linux with Kerberos and explain the ticket cache.
  9. Run a container, show its namespaces and capabilities, and explain why docker-group membership is root-equivalent.

Time. Spread it over Phase 1 (months 1–2). Do areas 1–6 in month 1 and areas 7–12 in month 2. Retake the gate at the end of month 2 and pass at least 7 of 9 before starting Phase 2.
